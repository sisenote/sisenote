# 决策记录模板

很多争论三个月后会被重新翻出来。这份模板把一次决策的背景、备选方案和依据写清楚，日后复盘、交接或反悔时都有据可查。复制到四色笔记后替换【】内容即可。

## 一、决策背景

- 决策事项：【要解决什么问题】
- 时间 / 参与者：【日期】｜【姓名】
- 约束条件：【时间、预算、资源等限制】
- <span class="sn-blue" data-sisenote-color="blue">概念：决策记录服务于「未来的读者」，要假设三个月后的自己完全不记得当时的讨论</span>

## 二、备选方案对比

| 方案 | 优点 | 主要风险 |
|---|---|---|
| 方案 A：【】 | 【】 | 【】 |
| 方案 B：【】 | 【】 | 【】 |

- <span class="sn-red" data-sisenote-color="red">重点：写清「为什么没选另一个方案」，这往往比选了什么更有价值</span>

## 三、最终决定与依据

- 最终选择：【方案】
- 关键依据：【数据 / 原则 / 过往经验】
- <span class="sn-green" data-sisenote-color="green">思路：给决策打个「置信度」分数，低置信度的决定要设一个复查时间点</span>
- 复查时间：【日期】

### 填表示例

> 选自建而非采购 → 依据：数据合规要求 + 三年成本更低 → 未选采购的原因：无法满足本地化部署 → 置信度 0.7 → 半年后复查。

## 四、结果回填与易错

- ☐ 实际结果：【决策落地后的真实效果】
- <span class="sn-yellow" data-sisenote-color="yellow">易错：不要只记成功的决策，失败决策的记录更能帮团队避开同一个坑</span>

## 五、使用建议

> 重大决策当场记录，趁记忆清晰。记录时保留当时的备选方案和反对意见，这些是日后判断决策质量的关键线索。把这件事养成习惯，团队就少了很多「我当时就说过」的争论。
