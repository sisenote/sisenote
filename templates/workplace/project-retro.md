# 项目复盘模板

复盘不是表扬与批评大会。这份模板先还原事实、再分析原因、最后沉淀经验，让团队把一次项目的得失变成下次可复用的能力。复制到四色笔记后替换【】内容即可。

## 一、项目回顾

- 项目目标：【当初要达成什么】
- 实际结果：【达成到什么程度，用数据说话】
- 关键时间线：【启动 → 里程碑 → 收尾】
- <span class="sn-blue" data-sisenote-color="blue">概念：复盘第一步是「还原事实」，先不评价、先不归因</span>

## 二、做对了什么与做错了什么

| 类别 | 具体事件 | 背后的原因 |
|---|---|---|
| 【做对】 | 【事件】 | 【为什么有效】 |
| 【做错】 | 【事件】 | 【为什么失效】 |

- <span class="sn-red" data-sisenote-color="red">重点：每条结论都要能回答「下次遇到同样情况该怎么做」，否则只是感慨</span>

## 三、根因分析

- 关键问题：【描述一个失误或亮点】
- <span class="sn-green" data-sisenote-color="green">思路：连问 3—5 个「为什么」，直到找到可行动的根因，而不是停在「沟通不畅」</span>
  - 为什么一：【】｜为什么二：【】｜为什么三：【】
- <span class="sn-yellow" data-sisenote-color="yellow">易错：把根因归为「人的问题」就停手，真正要改的往往是流程或机制</span>

### 填表示例

> 延期 2 周 → 需求变更 → 没有变更评审机制 → 缺少需求冻结节点 → 行动项：下个项目设立需求冻结日，负责人李四。

## 四、行动项与沉淀

- ☐ 【改进动作】｜负责人：【】｜完成时间：【】
- 可复用经验：【写进团队知识库 / 检查清单】

## 五、使用建议

> 复盘会上对事不对人，把结论写进模板，下次开工前先读一遍。沉淀下来的经验，才是一次项目真正的收益。
